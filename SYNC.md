# Automatic two-vault catalog maintenance

The computer-independent replacement is `.github/workflows/library-sync.yml`, using GitHub-hosted runners and direct Google Drive API authorization. See [CLOUD_SETUP.md](CLOUD_SETUP.md). GitHub stores the durable metadata masters; no local files, Codex sessions or connector tokens are required by that workflow. Complete its credential and Pages setup and verify a successful run before disabling the existing desktop routine. Until then the desktop routine still requires the computer awake and Codex running.

The owner also authorized personal Inbox organization on 2026-10-15: sort eligible personal Inbox descendants into category/subcategory folders within the personal vault, preserving names, bytes, IDs, access links, unrelated parents and permissions. Reuse existing folders, verify ancestry and moves, leave uncertain classifications in Inbox, never follow shortcuts and never move between vaults. Public Library remains read-only. `cloud_sync.py` performs this before scanning both vaults again and rebuilding. Current Drive parents and GitHub metadata masters support retry/recovery even after a runner is discarded. Local journals are temporary diagnostics, not required durable inputs.

The remaining steps describe the legacy desktop connector procedure. The cloud workflow uses the same ingestion, metadata masters, builder and verification rules with its own fully paginated Drive scanner, commit and direct Pages deployment.

## Every scheduled run

1. Read applicable instructions and the current remote main branch before changing anything. Bring the current metadata masters and builder into the workspace without resetting unrelated local work. Preserve manual edits. Organize personal Inbox as authorized above; Public Library, private Drive catalogs and the original Bookshelf repository remain read-only. Read the latest original Bookshelf catalog before merging missing upstream IDs. Run the combined sync even when Inbox is empty.
2. Execute `scan_vaults.js` in `functions.exec` with its connected tool namespace. It recursively lists only the configured vaults, retries transient folder reads, never follows shortcuts, and writes `latest_scan.local.json`. Use all pages when supported. A folder listing at the provider limit or a failed read makes the scan incomplete: do not ingest or advance the checkpoint. Never rely only on modified time: newly uploaded books can retain old modification dates. Every run traverses new folders as well as existing ones.
3. Run `python sync_catalog.py plan`. Review only new IDs within their own vault. Ignore catalog artifacts, software, web-page assets, covers and unrelated files. Existing entries survive temporary missing files; this workflow does not delete books or change sharing permissions. Never move anything across vaults. Before reading contents, use the scanned MIME type and source URL. Fetch bounded readable text where available for new-book credits, language and classification. Keep raw text and scans local. Unknown metadata remains Unknown; new uncertain entries stay marked for review. The owner’s Persian tagging rule applies to Persian-script filenames or author names and known Iranian authors, and must remain distinguishable from language verified in book text.
4. Optional verified additions go in `sync_additions.local.json`, keyed by `vault-id:Drive-file-id`, with a `fields` object using existing 15-column names. Never change Original ID or source link. The default ingestion is deliberately conservative. If refreshing the original Bookshelf catalog, save its current embedded data as `bookshelf_upstream.local.json`, then use `--upstream bookshelf_upstream.local.json`. Only missing IDs are imported automatically; conflicting corrections require reconciliation without erasing curated metadata. The personal metadata master retains additions even before the original catalog catches up.
5. Run `python sync_catalog.py apply` (with `--upstream` when available), then `python build_catalog.py`, `python verify_metadata.py`, and `python test_sync_catalog.py`. `public_library_catalog.csv` is the curated public-vault master; `bookshelf_source.json` is the personal-vault master. Existing fields are preserved. The builder supports growing counts, dates and vault-qualified identity, keeps include/exclude checkboxes, author filters and vault grouping, and emits separate and combined CSVs. The local pending transaction can replay interrupted writes while detecting concurrent edits. Run `python check_rebuild.local.py` when builder inputs change.
6. Re-read the remote branch head and affected masters before publication. If either changed, reconcile rather than forcing a stale overwrite. Use GitHub blob/tree/commit/ref tools to atomically publish changed catalog outputs and their required input snapshots together. Preserve all unrelated repository files. No book bytes, excerpts, raw text, signed download URLs, credentials, screening audit, local transaction files or operational logs may be published. Existing IDs, source paths and catalog-level provenance are authorized for this public repository. Allowed files: `index.html`, `catalog_data.json`, `book_catalog.csv`, `public_library_catalog.csv`, `bookshelf_catalog.csv`, `bookshelf_source.json`, `vault_inventory.json`, `metadata_source_order.json`, `metadata_evidence.json`, `metadata_audit.json`, `metadata_sources.md`, `sync_config.json`, `README.md`, `build_catalog.py`, `metadata_rules.py`, `catalog_ui.template.html`, `verify_metadata.py`, `sync_catalog.py`, `scan_vaults.js`, `test_sync_catalog.py`, `SYNC.md`, `.gitignore`, `.nojekyll`. Publish only changed files, excluding local-only data.
7. Verify the remote commit contents and deployed GitHub Pages embedded data/CSV/source files, using a fresh commit query string. Check both vault totals and their review flags independently; include/exclude controls and grouped results must remain intact. Only then run `python sync_catalog.py published --commit FULL_SHA`. Keep pending publication recoverable on any failure. Do not claim successful synchronization from a local build or a scheduled card alone.
8. If there are no additions, upstream changes or pending recovery, do not rebuild or commit. Record the check locally and stay quiet. Report meaningful additions, failures or required action only. A denied publication remains pending; do not bypass approval review.

The baseline has 1,416 Public Library entries and 500 original Bookshelf entries. These are regression minima, not fixed output sizes. Future additions remain scoped by vault and Drive ID, never deduplicated by title across sources.
